# DSL-Builder: сборка и запуск

Точка входа — `./cmd/dsl-builder`. Для сборки нужен Go 1.25; проект
использует только стандартную библиотеку. Готовый Windows x64 `.exe`
самостоятелен: установленный Go для его запуска не нужен.

Команды ниже выполняются из корня репозитория в Linux (Bash).
`v1.0.0` — пример явно заданной версии выпуска. При пересборке передайте
нужное значение через `-ldflags="-X main.buildVersion=..."`. Версии по
умолчанию нет: без этого значения программа отклоняет запуск.

Сборка консольного Windows x64 приложения без CGO:

```bash
mkdir -p dist
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -ldflags="-X main.buildVersion=v1.0.0" -o dist/dsl-builder.exe ./cmd/dsl-builder
```

Сборка и запуск для текущего Linux:

```bash
mkdir -p dist
CGO_ENABLED=0 go build -ldflags="-X main.buildVersion=v1.0.0" -o dist/dsl-builder ./cmd/dsl-builder
./dist/dsl-builder
```

В Windows откройте консоль в корне репозитория и запустите
`.\dist\dsl-builder.exe`, либо откройте `.exe`
двойным щелчком. Оба способа используют один интерактивный диалог.
Текущий рабочий каталог при запуске, полученный через `os.Getwd`, служит
базой относительных интерактивных путей; он может отличаться от каталога
самого `.exe`.

Выбирайте числа и нажимайте Enter: `1` — создать модуль, `2` — обновить,
`3` — добавить уроки, `4` — выйти. Пути, названия и веса вводятся в диалоге.
Параметры работы через аргументы, флаги, конфигурационные файлы или
переменные окружения не принимаются. При переданных аргументах программа
сообщает, что используется интерактивное меню.

`main` напрямую передаёт управление `console.Run`; диалог и создание
операций `app` принадлежат `console`. Код завершения `0` означает штатный
числовой выход или EOF с отменой незаписанного. Код `1` означает ошибку
подготовки запуска, потока либо вывода диагностики. Ошибку запуска или
`Run` программа передаёт в `console.PrintError` через stderr; повторной
печати при сбое самой диагностики нет. Скрытой паузы перед выходом нет,
поэтому для просмотра сообщений удобно запускать `.exe` из открытой консоли.

Поведение проверяется в Linux; сборка Windows x64 на Linux является
кросс-компиляцией. Нативный запуск Windows в этой среде не проверяется.
