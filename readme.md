# DSL-Builder

DSL-Builder — консольная утилита для сборки учебных модулей из технических
JSON, подготовленных парсером по контракту `1.0`. Она преобразует данные
в уроки, встраивает ресурсы и формирует манифест. Исходный DSL повторно
не разбирается: на вход нужны результаты парсера, а не файлы DSL.

Результат — плоский ZIP: `manifest.json` и файлы уроков `l001.json`,
`l002.json`, …, `l1000.json`. Все записи находятся в корне архива.
Медиа и сопутствующие файлы хранятся внутри JSON в Base64.

## Режимы работы

| Пункт меню | Режим | Что потребуется |
|---|---|---|
| `1` | Создать новый модуль | Каталог технических JSON, название курса, необязательное название юнита |
| `2` | Обновить существующий модуль | ZIP модуля и ровно один технический JSON |
| `3` | Добавить уроки | ZIP модуля и один технический JSON либо каталог JSON |
| `4` | Выход | — |

При создании и добавлении каталоги JSON обходятся рекурсивно.
Обновление находит урок по стабильному `document.metadata.documentId`.
Добавление требует новых ID, не совпадающих с уже существующими.
У неизменённых уроков сохраняются содержимое, ID, ревизии и технические имена.

## Требования и получение исходников

Для сборки нужен **Go 1.25 или новее** (`go.mod`: `1.25.0`).
Проект использует только стандартную библиотеку; устанавливать сторонние
зависимости не требуется. Для клонирования нужен Git.
Готовая утилита самостоятельна: установленный Go для запуска не нужен.
Основной выпуск — консольное приложение Windows x64.

```sh
git clone https://github.com/verdoga/dsl-builder.git
cd dsl-builder
```

## Сборка и запуск

Все команды сборки выполняются из корня репозитория.
Версию необходимо задать через `-ldflags="-X main.buildVersion=..."`.
`v1.0.0` ниже — пример версии выпуска. Без заданной версии программа
отклоняет запуск.

### Windows x64 — PowerShell

```powershell
New-Item -ItemType Directory -Force dist | Out-Null
$env:GOOS='windows'
$env:GOARCH='amd64'
$env:CGO_ENABLED='0'
go build -ldflags="-X main.buildVersion=v1.0.0" -o dist/dsl-builder.exe ./cmd/dsl-builder
.\dist\dsl-builder.exe
```

Можно также открыть готовый `.exe` двойным щелчком. Для удобного просмотра
сообщений запускайте его из уже открытой консоли.

### Linux x64 — Bash

```bash
mkdir -p dist
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -ldflags="-X main.buildVersion=v1.0.0" -o dist/dsl-builder ./cmd/dsl-builder
./dist/dsl-builder
```

### Сборка Windows x64 из Linux — Bash

```bash
mkdir -p dist
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -ldflags="-X main.buildVersion=v1.0.0" -o dist/dsl-builder.exe ./cmd/dsl-builder
```

Полученный `dist/dsl-builder.exe` запускается в Windows.

## Работа с утилитой

1. Запустите программу, введите номер режима и нажмите Enter.
2. Укажите входные пути и запрошенные названия в диалоге.
3. Изучите предварительный просмотр состава, изменений и ресурсов.
4. При необходимости измените курс, юнит, секции, их порядок или веса уроков
   через доступные пункты меню. После правок просмотрите обновлённый план.
5. Выберите запись и подтвердите показанный результат: `1. Да` / `2. Нет`.
   Для существующего целевого файла дополнительно подтвердите перезапись.

При создании каталог назначения и имя ZIP запрашиваются отдельно;
расширение `.zip` добавляется, если оно не указано. Обновление и добавление
сохраняют результат по пути выбранного архива.

В предварительном просмотре обновления видны уровень замены, старые и новые
ID, переход ревизии урока и изменения манифеста. Изменения названий урока,
подзаголовка и страниц подтверждаются отдельно. При отсутствии изменений
архив не переписывается.

Относительные пути, вводимые в диалоге, считаются от текущего рабочего
каталога при запуске, который может отличаться от каталога `.exe`.
Пути с пробелами можно вставлять с внешней парой кавычек.
Пути к JSON и ZIP и все параметры операции вводятся только в диалоге.
Аргументы командной строки, флаги, конфигурационные файлы и переменные
окружения не задают параметры работы утилиты.

## Входные данные и ресурсы

Технический JSON должен быть в UTF-8 и соответствовать
[Contract.jsonc](Contract.jsonc), `formatVersion: "1.0"`.
Нужен корректный уникальный ID урока; признаки ошибок парсера блокируют
сборку. Исходные JSON и файлы ресурсов утилита не изменяет.

Автоматический поиск ресурсов ограничен каталогами, объявленными в
`document.metadata.resourceDirs`, и их подкаталогами. Относительные
ресурсные пути считаются от каталога конкретного технического JSON.
Без `resourceDirs` доступны только явные пути к медиа.

Поддерживаются аудио, видео и изображения. Рядом с найденным аудио или
видео подключаются одноимённые TXT-расшифровки и субтитры VTT, SRT, TTML,
DFXP, ASS и SSA. Байты встраиваются в Base64 без перекодирования.
Полный перечень расширений приведён в [ТЗ, раздел 9](TZ.md#9-поиск-и-встраивание-ресурсов).
В предварительном просмотре доступны счётчики и список неиспользованных ресурсов.

Отсутствующие или неоднозначные обязательные ресурсы, конфликты ID и весов,
ошибки входных данных и несогласованность ZIP блокируют запись результата.
После исправления данных можно повторить анализ или вернуться в меню.
До подтверждения записи исходный архив не изменяется; отказ или окончание
ввода отменяют незаписанную операцию.
